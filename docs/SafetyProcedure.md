# 実機のアームを動かすときの安全手順

実機の VP-6242(2 台)を、このソフトウェアで初めて動かすときと、普段の測定の前の手順です。
**ソフトウェア側の補足**であり、ロボットとコントローラの取扱説明書(VP ロボット取扱説明書の「安全上のご注意」、RC8 シリーズロボットコントローラ説明書)が優先します。

状態: 手順とソフトウェア側の防御は実装した(§1)が、**実機ではまだ一度も試していない**。実機で確かめるまで当てにできない部分は、§1 の表に書いてある。

## 0. 前提

- **動作中にコードから止められるかは、実機で確かめるまで分からない。** 既定(`abortable_moves = false`)の移動は、動作が終わるまで戻る呼び出し 1 つで、動作中の Ctrl+C は効かない(次の姿勢へ進む前には止まる)。動作中も止められる移動(`abortable_moves = true`)は作ってあるが、実機で確かめていない(§7 の 6)。**止める手段は、ティーチングペンダントの非常停止スイッチ**。動かすあいだは、手が届く位置にいる。
- ソフトウェアの防御は、人間の確認の代わりにならない。最初の数回は、必ずアームを目で見ながら動かす。
- 動かす前に分かっていることと、分かっていないこと(§2)を区別する。

## 1. ソフトウェアの防御の現状

| 防御 | 状態 |
|---|---|
| 送る前の可動域チェック(`[arm.limits]`、既定は VP-6242 の出荷時のソフトウェアリミット) | 実装済み |
| 移動後の到着確認(エンコーダ。既定の許容 1°) | 実装済み |
| モータは移動の間だけ ON。失敗しても必ず OFF に戻す | 実装済み |
| 時間切れ・通信の途切れで、止める → モータ OFF → 切断 | 実装済み |
| **速度の上限**(`[controllers] max_speed`、既定 5%)。レシピの `arm_speed` がこれより大きくても、上限で動かす | 実装済み(`brdf run`、`calibrate`、`arm` のすべてに効く) |
| **動かす前の確認表示**(装置、実際の速度、動かす範囲、中止の方法)と、OK の入力。`--yes` でも省略できない | 実装済み(`brdf run`、`calibrate`、`arm move`) |
| **現在位置のチェック**: 接続した直後に、アームの実際の位置を読み、そこから最初の姿勢までの道のりを検査。問題があれば何も動かさない | 実装済み(`brdf run`、`calibrate`)。`arm move` は、もう一方の実際の位置も読んで検査する |
| アーム同士の干渉チェック(実行前)。**姿勢の間の移動は、途中の点(20 点)も調べる** | 実装済み(アームを半径 60 mm の棒とした近似。カメラ・分光放射計・床・台・試料の板は含まない) |
| 旧システムの実績範囲の外の姿勢を警告する(余裕 15°) | 実装済み(実機モードのときだけ。警告であり、止めない) |
| 失敗したとき、両方のアームを止めてから切断する | 実装済み |
| 姿勢の切り替わりでの中止(Ctrl+C)。次の姿勢へ進まず、止まる | 実装済み |
| **動作中の中止**(`abortable_moves = true`): 移動を非同期で始め、関節角を読みながら待ち、Ctrl+C で `Halt` → モータ OFF | 実装済み。**実機で未確認**(§7 の 6)。既定は無効 |
| 1 台ずつ動かす `brdf arm status` / `brdf arm move`(§4 の各段階で使う) | 実装済み |

実機モード(`mode = "real"`)の `brdf run` / `calibrate` / `arm` は、`-DBRDF_WITH_BCAP=ON` と `-DBRDF_WITH_TOPCON=ON` の**両方**を付けてビルドしたときだけ動く(どちらかがなければ、足りないものを案内するエラーで止まる)。

## 2. 旧システムの実績

旧システムの姿勢ファイル(`RJ1..RJ6, LJ1..LJ6` の CSV)19 個、370 行を集めて、関節ごとの最小・最大を調べた(2026-11)。
測定のために作られた姿勢の値であり、**実際に全部を動かしたとは限らない**。また、これは「動かしたことのある範囲」であって、「安全な限界」ではない。

| 関節 | 右(試料側、RJ) | 左(光源側、LJ) | 出荷時のソフトウェアリミット |
|---|---|---|---|
| J1 | −85 〜 −30 | 0 〜 85 | ±160 |
| J2 | −20 〜 45 | −20 〜 40 | ±120 |
| J3 | 20 〜 125 | 90 〜 110 | +19 〜 +160 |
| J4 | −20 〜 15 | −45 〜 40 | ±160 |
| J5 | −20 〜 15 | −115 〜 0 | ±120 |
| J6 | −30 〜 30 | −70 〜 65 | ±360 |

(単位は度)

分かったこと:

- **どの姿勢も、出荷時のソフトウェアリミットの内側**に収まっている。リミットをコントローラ側で狭めている可能性は、実機で確認する(§3 の 3)。
- 右アームは J1 が負の側、左アームは J1 が正の側に振る(2 台の土台は 945 mm 離れている)。
- J3 = 90° が「前腕が水平」で、ほとんどの姿勢がその近く。
- **標準姿勢**: 右 `(-45, 0, 90, 0, 0, 0)`、左 `(45, 0, 90, 0, 0, 0)`。旧システムの試験用の姿勢ファイルが、繰り返し使っている。最初の動作確認の目標にする。
- **IP と左右の対応**: 旧システムのコードは、右アームの姿勢(`RJ`)を `192.168.0.5` に、左アーム(`LJ`)を `192.168.0.2` に送っていた。新しいものの既定値(`[controllers]`)は同じ。
- 旧システムのコードに現れる速度の値は、1%、10%、15%、40%(一部はコメントアウトされている)。
- 旧システムには、可動範囲・干渉・速度の安全チェックは**なかった**(「OK と入力してください」の確認だけ)。

## 3. 動かす前に確かめること(チェックリスト)

### 場所

1. 2 台のアームの届く範囲に、人がいない。
2. 届く範囲から、**カメラ、分光放射計、試料の板、ケーブル、台、荷物を外す**。最初の確認は、何もない状態で行う。
3. ティーチングペンダントが手元にあり、**非常停止スイッチに手が届く**。ペンダントのモードを確認する(自動 / マニュアル。`Takearm` が通るモードは、実機で確かめる)。
4. 床に、2 台の土台の位置(世界座標の原点が左アームの土台、右は 945 mm 離れている)の目印がある。`setup.toml` の `[rig]` と合っている。

### コントローラ

1. 両方のコントローラの電源が入り、エラーが出ていない。
2. コントローラのソフトウェアリミットが、出荷時の設定から変えられていないか確認する。**広げられているなら、`[arm.limits]` は、安全に使える範囲に狭めたままにする**(送る前のチェックが、その外を断る。コントローラが自分のリミットで断るのは、その外側)。狭められているなら、`[arm.limits]` もそれに合わせる(合わせないと、コントローラが断るまで気づかない)。
3. IP アドレスが、`[controllers]` と合っている(PC のネットワーク設定も)。

### ソフトウェア

1. `devices.mode = "real"`、`[controllers]`、`[arm.limits]` を確認する。
2. `brdf check` で、エラーが 0 件(干渉、可動域)。
3. `brdf view` で動きを見て、姿勢の間の動きと、2 台の近づき方に違和感がない。**カメラ・試料の板など、チェックに含まれていないものとの距離は、ここで目で見る**。
4. 速度は、最初は **5%**。

## 4. 段階的な手順

各段階で、問題がなければ次へ進む。**問題があれば、そこで止めて原因を調べる**(§5)。

| 段階 | 内容 | 確認すること |
|---|---|---|
| 0 | シミュレータで同じレシピを実行する(`mode = "sim"`) | エラーなし。`brdf view` で動きを確認 |
| 1 | **接続だけ**。接続して、`currentJoints()` で現在の関節角を読み、切断する。**動かさない** | 接続できる。読んだ角度が、ペンダントの表示と合う(度の単位、J1〜J6 の順)。切断後、制御権が返っている |
| 2 | 1 台だけ。現在位置のすぐ近く(関節 1 つを 2〜3° だけ)に、速度 5% で動かす | 目で見て、予想通りに動く。到着確認が通る。小数の角度(例: 2.5°)も通る。動いたあとのモータの状態 |
| 3 | 同じアームを標準姿勢に、速度 5% で動かす。**現在位置から標準姿勢までの道のりを、先に確かめる** | 道のりに障害物がない。動作時間(`move_timeout_ms` が十分か) |
| 4 | **左右の対応**。IP の `.2` と `.5` のどちらが、光源側(左、`LJ`)か、目で確かめる。片方ずつ動かす | 光源側のアームが動いたのは `.2` か(旧システムのコードでは `.2` が左) |
| 5 | もう 1 台も同じように標準姿勢へ。そのあと、2 台とも標準姿勢にした状態で、近づき具合を目で確認 | 2 台の間隔、手首の高さ |
| 6 | レシピの姿勢を 1 つだけ動かす。速度 5% → 10% → 20% → 40% と上げる(旧システムのコードに現れる最大が 40%)。**最初の速度は 5% から始め、いきなり上げない** | 速度を上げても、到着確認が通る |
| 7 | レシピの全姿勢を、速度 5% で通しで動かす(分光放射計は付けない) | 全姿勢で到着。時間(`Motor` ON の時間を含む) |
| 8 | カメラ・試料の板・分光放射計を付けて、同じ姿勢を通しで動かす | 付けたものとの距離。**付けたあとで、最初の 1 姿勢を低速で、目で見ながら** |

各段階で使うコマンド(プロジェクトフォルダは `<project>`。`setup.toml` を `mode = "real"` にしておく):

```bash
brdf arm status <project>                            # 段階 1: 両方の現在の関節角を読む(動かさない)
brdf arm move <project> --arm right --jog 1=2.5      # 段階 2: 右アームの J1 を +2.5° だけ(速度は既定 5%)
brdf arm move <project> --arm right --standard       # 段階 3: 標準姿勢へ
brdf arm move <project> --arm left --standard        # 段階 4・5: 左アームも
brdf check <project>                                 # 段階 6 の前: 可動域・干渉・途中の干渉
brdf run <project>                                   # 段階 7・8
```

`brdf arm move` は、動かす前に、**もう一方のアームの実際の位置も読んで**、可動域・干渉・途中の干渉を検査し、確認表示で `OK` の入力を求める。
速度は `--speed`(0〜1 の割合)で変えられるが、`[controllers] max_speed` を超えない。
`--to=-45,0,90,0,0,0`(絶対角。`=` でつなぐ)、`--standard`、`--jog N=DEG` のどれか 1 つを指定する。

**段階 2b: 動作中の中止を確かめる**(段階 2 のあと、必ず非常停止に手を置いて): `setup.toml` の `abortable_moves = true` にして、
`brdf arm move <project> --arm right --jog 1=10` を速度 5% で動かし、動いている途中で Ctrl+C を押す。
アームが止まり、モータが OFF になり、`Cancelled` が報告されることを確かめる。止まらない、止まるのが遅い、動作が完了を待たずに終わる
(`NEXT` が効いていない)などの場合は、`abortable_moves` を `false` に戻し、結果を §7 の 6 に書く。

段階 1〜4 で測れたことは、[docs/Rc8ArmDesign.md](Rc8ArmDesign.md) の §7(未確認の点)の表に、結果を書き込む。

## 5. 中止の基準と、止めたあと

次のどれかがあったら、**その場で非常停止**する(段階的な手順の途中でも、普段の測定でも)。

- アームが、予想と違う方向に動く、速すぎる、止まらない。
- 異音、異常な振動。
- 動作中に、人や物が届く範囲に入った。
- ソフトウェアが、時間切れ(`Timeout`)や通信エラー(`Communication`)を報告した。この場合、アームがまだ動いているかもしれない。ソフトウェアは、止める → モータ OFF → 切断を試みるが、**届いたかは分からない**ので、目で確かめる。
- 到着確認のエラー(「目標に着いていない」)。命令が無視された、または、動作が途中で止まった。

止めたあと:

1. **すぐに再開しない**。何が起きたかを確認する(ログ、コントローラのエラー表示)。
2. アームの状態(モータ、制御権、現在位置)を、ペンダントで確認する。
3. 原因が分かるまで、速度を上げない。同じ段階の、もっと遅い速度からやり直す。
4. 原因と、再開した条件を、記録に残す。

## 6. 動かし終わったあと

1. 切断が終わり、制御権が返っている(ペンダントから操作できる状態)ことを確認する。
2. モータが OFF になっている(ブレーキがかかっている)ことを確認する。
3. 取り外したカメラ・試料の板などを、元に戻す前に、その日の記録(速度、姿勢、問題点)を書く。

## 7. 実装した防御と、実機で確かめること(P6 ⑤)

実装した(§1)。実機で確かめることは次の通り。

1. **速度の上限**: 既定は 5%。上げるときは、`setup.toml` の `max_speed` を、意識して変える。確認表示に、実際の速度と、制限したことが出る。
2. **動かす前の確認表示**: 装置の IP とポート、実際の速度、全姿勢での関節ごとの範囲、中止の方法、周りの確認。
3. **現在位置からの道のりのチェック**: 接続した直後に現在の関節角を読む(`CurJnt`)。**実機で、この値がペンダントの表示と合うことを、段階 1 で確かめる**。
4. **実績範囲の外の警告**: §2 の範囲から 15° を超えて外れる関節を警告にする。
5. **両アームの後始末**: 失敗したら、両方に `Halt` を送ってから切断する(それぞれモータ OFF、制御権を返す)。
6. **動作中の中止**: 次の設計になっている。
   - 移動を**非同期**で始める(RC8 の `Move` の `Next` オプション。マニュアルでは「非同期で移動」。`bCap_RobotMove` のオプション文字列 `"NEXT"`)。`moveJ` は、`CurJnt` を 0.1 秒ごとに読んで、目標に着くまで待つ。「着いた」は、読み取りが 3 回続けて動かず(0.05° 未満)、かつ目標との差が許容(1°)以内のとき。
   - 待つ間、**中止の旗**(Ctrl+C のハンドラが立てる)を見る。旗が立ったら、同じソケットで `Halt` を送り、モータを OFF にして、`Cancelled` のエラーで戻る。ソケットを使うのは `moveJ` を呼んだスレッド 1 つだけ。
   - 動き出さない(猶予 3 秒)、途中で止まった、期限(`move_timeout_ms`)までに終わらない、のどれも、エラーにする(期限切れは、状態が分からないので、止めて切断する)。
   - 2 回目の Ctrl+C は、既定の動作(プロセスの終了)に戻る(中止の処理が進まないときに、止められなくならないように)。
   - **実機で確かめること**: `NEXT` が、本当に動作の完了を待たずに戻るか(待ってしまっても、監視は正しく終わる)。`Halt` が、動作中に効くか、どのくらいの距離で止まるか。確かめるまでは、`abortable_moves = false` のままにする。
   - **限界**: `Halt` は、ソフトウェアからの減速停止であり、非常停止ではない。通信が途切れていれば届かない。非常停止スイッチの代わりにはならない。

まだない防御:

- カメラ・分光放射計・床・台・試料の板との干渉チェック(今は、2 台のアーム同士だけ)。
- 左右のアームと IP の対応の自動確認(段階 4 で、目で確かめる)。
