# 実機のアームを動かすときの安全手順

実機の VP-6242(2 台)を、このソフトウェアで初めて動かすときと、普段の測定の前の手順です。
**ソフトウェア側の補足**であり、ロボットとコントローラの取扱説明書(VP ロボット取扱説明書の「安全上のご注意」、RC8 シリーズロボットコントローラ説明書)が優先します。

状態: 手順は書いたが、**実機ではまだ一度も試していない**。ソフトウェア側の防御の一部は未実装(§1)。

## 0. 前提

- 動作中に、プログラムからアームを止めることはできない(`moveJ` は動作が終わるまで戻り、その間に `stop()` は呼べない)。**止める手段は、ティーチングペンダントの非常停止スイッチ**。動かすあいだは、手が届く位置にいる。
- ソフトウェアの防御は、人間の確認の代わりにならない。最初の数回は、必ずアームを目で見ながら動かす。
- 動かす前に分かっていることと、分かっていないこと(§2)を区別する。

## 1. ソフトウェアの防御の現状

| 防御 | 状態 |
|---|---|
| 送る前の可動域チェック(`[arm.limits]`、既定は VP-6242 の出荷時のソフトウェアリミット) | 実装済み |
| 移動後の到着確認(エンコーダ。既定の許容 1°) | 実装済み |
| モータは移動の間だけ ON。失敗しても必ず OFF に戻す | 実装済み |
| 時間切れ・通信の途切れで、止める → モータ OFF → 切断 | 実装済み |
| アーム同士の干渉チェック(実行前。姿勢の間の移動中も) | 実装済み(アームを半径 60 mm の棒とした近似。カメラ・分光放射計・床・台・試料の板は含まない) |
| **実機モードの速度の上限** | **未実装**(今は `arm_speed` が 1.0 まで通る) |
| **動かす前の確認表示**(どの装置が、どの速度で、どの姿勢へ) | **未実装**(実機モードが `brdf run` につながっていない) |
| **現在位置から最初の姿勢までの道のりのチェック** | **未実装**(今のチェックはレシピの姿勢の間だけ) |
| **旧システムの実績範囲の外を警告する** | **未実装**(§2) |

未実装の 4 つは、**実機で動かす前に実装する**(P6 ⑤)。それまでは、このソフトウェアで実機のアームを動かさない。

## 2. 旧システムの実績

旧システムの姿勢ファイル(`RJ1..RJ6, LJ1..LJ6` の CSV)19 個、370 行を集めて、関節ごとの最小・最大を調べた(2026-11)。
測定のために作られた姿勢の値であり、**実際に全部を動かしたとは限らない**。また、これは「動かしたことのある範囲」であって、「安全な限界」ではない。

| 関節 | 右(試料側、RJ) | 左(光源側、LJ) | 出荷時のソフトウェアリミット |
|---|---|---|---|
| J1 | −85 〜 −30 | 0 〜 85 | ±160 |
| J2 | −20 〜 45 | −20 〜 40 | ±120 |
| J3 | 20 〜 125 | 90 〜 110 | +19 〜 +160 |
| J4 | −20 〜 15 | −45 〜 40 | ±160 |
| J5 | −20 〜 15 | −115 〜 0 | ±120 |
| J6 | −30 〜 30 | −70 〜 65 | ±360 |

(単位は度)

分かったこと:

- **どの姿勢も、出荷時のソフトウェアリミットの内側**に収まっている。リミットをコントローラ側で狭めている可能性は、実機で確認する(§3 の 3)。
- 右アームは J1 が負の側、左アームは J1 が正の側に振る(2 台の土台は 945 mm 離れている)。
- J3 = 90° が「前腕が水平」で、ほとんどの姿勢がその近く。
- **標準姿勢**: 右 `(-45, 0, 90, 0, 0, 0)`、左 `(45, 0, 90, 0, 0, 0)`。旧システムの試験用の姿勢ファイルが、繰り返し使っている。最初の動作確認の目標にする。
- **IP と左右の対応**: 旧システムのコードは、右アームの姿勢(`RJ`)を `192.168.0.5` に、左アーム(`LJ`)を `192.168.0.2` に送っていた。新しいものの既定値(`[controllers]`)は同じ。
- 旧システムのコードに現れる速度の値は、1%、10%、15%、40%(一部はコメントアウトされている)。
- 旧システムには、可動範囲・干渉・速度の安全チェックは**なかった**(「OK と入力してください」の確認だけ)。

## 3. 動かす前に確かめること(チェックリスト)

### 場所

1. 2 台のアームの届く範囲に、人がいない。
2. 届く範囲から、**カメラ、分光放射計、試料の板、ケーブル、台、荷物を外す**。最初の確認は、何もない状態で行う。
3. ティーチングペンダントが手元にあり、**非常停止スイッチに手が届く**。ペンダントのモードを確認する(自動 / マニュアル。`Takearm` が通るモードは、実機で確かめる)。
4. 床に、2 台の土台の位置(世界座標の原点が左アームの土台、右は 945 mm 離れている)の目印がある。`setup.toml` の `[rig]` と合っている。

### コントローラ

1. 両方のコントローラの電源が入り、エラーが出ていない。
2. コントローラのソフトウェアリミットが、出荷時の設定から変えられていないか確認する。**広げられているなら、`[arm.limits]` は、安全に使える範囲に狭めたままにする**(送る前のチェックが、その外を断る。コントローラが自分のリミットで断るのは、その外側)。狭められているなら、`[arm.limits]` もそれに合わせる(合わせないと、コントローラが断るまで気づかない)。
3. IP アドレスが、`[controllers]` と合っている(PC のネットワーク設定も)。

### ソフトウェア

1. `devices.mode = "real"`、`[controllers]`、`[arm.limits]` を確認する。
2. `brdf check` で、エラーが 0 件(干渉、可動域)。
3. `brdf view` で動きを見て、姿勢の間の動きと、2 台の近づき方に違和感がない。**カメラ・試料の板など、チェックに含まれていないものとの距離は、ここで目で見る**。
4. 速度は、最初は **1〜5%**。

## 4. 段階的な手順

各段階で、問題がなければ次へ進む。**問題があれば、そこで止めて原因を調べる**(§5)。

| 段階 | 内容 | 確認すること |
|---|---|---|
| 0 | シミュレータで同じレシピを実行する(`mode = "sim"`) | エラーなし。`brdf view` で動きを確認 |
| 1 | **接続だけ**。接続して、`currentJoints()` で現在の関節角を読み、切断する。**動かさない** | 接続できる。読んだ角度が、ペンダントの表示と合う(度の単位、J1〜J6 の順)。切断後、制御権が返っている |
| 2 | 1 台だけ。現在位置のすぐ近く(関節 1 つを 2〜3° だけ)に、速度 1% で動かす | 目で見て、予想通りに動く。到着確認が通る。小数の角度(例: 2.5°)も通る。動いたあとのモータの状態 |
| 3 | 同じアームを標準姿勢に、速度 1〜5% で動かす。**現在位置から標準姿勢までの道のりを、先に確かめる** | 道のりに障害物がない。動作時間(`move_timeout_ms` が十分か) |
| 4 | **左右の対応**。IP の `.2` と `.5` のどちらが、光源側(左、`LJ`)か、目で確かめる。片方ずつ動かす | 光源側のアームが動いたのは `.2` か(旧システムのコードでは `.2` が左) |
| 5 | もう 1 台も同じように標準姿勢へ。そのあと、2 台とも標準姿勢にした状態で、近づき具合を目で確認 | 2 台の間隔、手首の高さ |
| 6 | レシピの姿勢を 1 つだけ動かす。速度 5% → 10% → 20% → 40% と上げる(旧システムの実績は 40% まで) | 速度を上げても、到着確認が通る |
| 7 | レシピの全姿勢を、速度 5% で通しで動かす(分光放射計は付けない) | 全姿勢で到着。時間(`Motor` ON の時間を含む) |
| 8 | カメラ・試料の板・分光放射計を付けて、同じ姿勢を通しで動かす | 付けたものとの距離。**付けたあとで、最初の 1 姿勢を低速で、目で見ながら** |

段階 1〜4 で測れたことは、[docs/Rc8ArmDesign.md](Rc8ArmDesign.md) の §7(未確認の点)の表に、結果を書き込む。

## 5. 中止の基準と、止めたあと

次のどれかがあったら、**その場で非常停止**する(段階的な手順の途中でも、普段の測定でも)。

- アームが、予想と違う方向に動く、速すぎる、止まらない。
- 異音、異常な振動。
- 動作中に、人や物が届く範囲に入った。
- ソフトウェアが、時間切れ(`Timeout`)や通信エラー(`Communication`)を報告した。この場合、アームがまだ動いているかもしれない。ソフトウェアは、止める → モータ OFF → 切断を試みるが、**届いたかは分からない**ので、目で確かめる。
- 到着確認のエラー(「目標に着いていない」)。命令が無視された、または、動作が途中で止まった。

止めたあと:

1. **すぐに再開しない**。何が起きたかを確認する(ログ、コントローラのエラー表示)。
2. アームの状態(モータ、制御権、現在位置)を、ペンダントで確認する。
3. 原因が分かるまで、速度を上げない。同じ段階の、もっと遅い速度からやり直す。
4. 原因と、再開した条件を、記録に残す。

## 6. 動かし終わったあと

1. 切断が終わり、制御権が返っている(ペンダントから操作できる状態)ことを確認する。
2. モータが OFF になっている(ブレーキがかかっている)ことを確認する。
3. 取り外したカメラ・試料の板などを、元に戻す前に、その日の記録(速度、姿勢、問題点)を書く。

## 7. このソフトウェアの実装予定(P6 ⑤)

実機モードを `brdf run` につなぐときに、次を入れる。

1. **実機モードの速度の上限**(`[controllers]` に設定。最初は低い値を既定にする)。
2. **動かす前の確認表示**: どの装置を、どの速度で、いくつの姿勢へ動かすかを表示して、確認を取る。
3. **現在位置からの道のりのチェック**: 接続した直後に現在の関節角を読み、そこから最初の姿勢までの道のりを、レシピの姿勢の間と同じチェックにかける。
4. **実績範囲の外の警告**: 旧システムの実績(§2)の範囲から大きく外れる姿勢を、警告にする(エラーではない)。
5. 実機モードで失敗したときの、**両方のアームの後始末**(どちらかが失敗しても、もう一方のモータを OFF にして切断する)。
