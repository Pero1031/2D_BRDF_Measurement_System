# 新システム 設計・開発計画(案)

前提資料: [LegacySystemAnalysis.md](LegacySystemAnalysis.md)(旧システムの解析)

## 0. 目的と方針

| 目的 | 方針 |
|---|---|
| 旧システムと**同じ機能**を実現する | 旧の測定フローを、そのままの順序で再現する(§2) |
| 引継ぎしやすく、**わかりやすい**構造にする | 責務ごとに分割し、各部分を単体でテスト・説明できるようにする |
| **絶対パスと手作業の設定をなくす** | プロジェクトフォルダ方式と設定ファイル(TOML)にする |
| 最初は**モックだけで**動かす | 物理的に妥当なシミュレータを作り、実機なしで最後まで通す |
| 実機は**後から差し替える** | ドライバのインターフェースだけに依存した設計にする |

設計の原則は次の 4 つです。

1. **計算は純粋関数にする。** 順運動学、角度計算、ホモグラフィは、表示・ファイル選択・`cin`・`exit()` を持たない。
2. **装置は差し替え可能にする。** 実機とモックは同じインターフェースの別実装にする。
3. **設定とデータは、すべてプロジェクトフォルダ内の相対パスにする。**
4. **旧システムの出力を正解として、新しい計算を検証する**(§4)。

### 1.2 プロジェクトフォルダ(絶対パスをなくす仕組み)
測定 1 件(1 試料・1 日分)を 1 フォルダにまとめ、プログラムはそのパスだけを受け取ります。

```
my_measurement/
├─ project.toml        名前、担当者、メモ、使用する setup / recipe
├─ setup.toml          装置の配置(カメラ位置、光源オフセット、リンク長…)
├─ recipe.toml         ポーズ一覧、試料、測定点、積分条件
├─ calibration/        キャリブボード画像、ホモグラフィ、仮想ボード定義
├─ white/              白色板の測定データ
├─ result/             試料の測定データ、角度表、ログ
└─ run_manifest.toml   実行時の設定・日時・バージョン(自動保存)
```

- 旧システムの `D:/Data/...` や、ヘッダに書き込んでいた `SpectrometerParam` の値は、すべて `setup.toml` に移します。
- 実行のたびに `run_manifest.toml` へ設定のコピーと日時を残します。**後から条件が追える**ので、引継ぎ資料の代わりにもなります。

## 3. モックの設計(最初の主役)

「何も測らない空のモック」ではなく、**簡易的に物理を再現するシミュレータ**にします。

### 3.1 `SimulatedRig`(世界の状態)
- 左右アームの関節角、カメラ位置、光源オフセット、試料の位置を持つ。
- `MockRobotArm` が動くと、ここが更新される。
- `MockImager` が、ここから「今の幾何」を読み取る。

### 3.2 `MockImager`(2D 分光放射計の代わり)
1. 呼ばれたときの幾何を `SimulatedRig` から取得する。
2. 測定点ごとに、`optics::computeAngles` で (θi, φi, θo, φo) を求める。
3. **既知の BRDF モデル**(最初は Lambert、次に Phong、将来は GGX など)から、点ごとの分光値を計算する。
4. 積分時間に比例するスケールとノイズを加える。
5. 本物と同じ形式(`[Spectral]` セクションを持つ CSV)で返す。

こうすると**結果の正しさを検証できます**。つまり、シミュレーションで得た測定値から BRDF を復元し、設定した真のモデルと比べられます。これが、モック段階で実機に近い品質を確認する最大の利点です。

### 3.3 `MockRobotArm` の拡張
- 関節可動域を超える指令はエラーにする。
- **左右アームの干渉チェック**を、モックの段階で入れる(実機で最も怖い失敗を、先に防ぐ)。
- 目標への到達までに時間がかかる設定(`--sim-speed`)も用意する。

### 3.4 失敗の再現
通信断、可動域外、タイムアウトを、モックから意図的に起こせるようにします。エラー処理を実機の前に試験できます。

## 4. 検証戦略(旧システムを「正解」として使う)

旧システムの出力が残っているので、それと新システムを突き合わせます。

| 照合の対象 | 旧データ(正解) | 見るもの |
|---|---|---|
| 順運動学と角度計算 | `D:\Data\AngleTable\out1〜3.csv`(姿勢 → θ/φ の約 11.8 万行 × 3) | 姿勢を入力して、θ/φ が許容誤差内で一致するか |
| 試料点ごとの角度 | `AgInkBeta\AngleInfo\AgInkBeta_*.csv` | 試料点の角度が一致するか |
| ホモグラフィ | `AgInkBeta\Homography\`、`CalibBoard\` | 行列の値、スポット位置 |
| スポット XML | `AgInkBeta\spotdata\*.xml` | `AreaCenter` が一致するか |
| 旧版の動作記録 | `SoftwareTest\movearm出力結果.txt` | 関節角 → 先端位置 |

注意: 旧データを取った時点の装置パラメータ(カメラ位置など)が、今のヘッダと違う可能性があります。照合では、まずパラメータを合わせてから比較します。合わないものは、**旧コードのバグか、パラメータの違いか**を切り分けて記録します。

その他のテスト:
- 単体テスト: 行列の回転、角度の境界値(θ=0、φ の象限)、CSV/XML の入出力。
- シミュレーション往復テスト: 設定した BRDF → 測定 → 復元 → 誤差が小さいこと。
- 設定の検証テスト: 欠けた項目や不正値で、わかりやすいエラーメッセージが出ること。

## 5. 開発の進め方(フェーズ)

| フェーズ | 内容 | 完了の目安 |
|---|---|---|
| **P0 土台** | CMake 化、テスト枠組み(Catch2 など)、ログ、エラー型、`.editorconfig`、フォルダ構成 | `cmake --build` と `ctest` が通る |
| **P1 幾何と角度** | `Pose`、`Rc8Kinematics`、`computeAngles`。旧データとの照合 | `out1.csv` が許容誤差内で再現できる |
| **P2 ドライバ v2 とシミュレータ** | `IRobotArm` の整理、`ISpectralImager` の新設、`SimulatedRig` と各モック、BRDF モデル | シミュレーションで 1 ポーズを測定できる |
| **P3 プロジェクトとセッション** | `ProjectLayout`、TOML(`setup`/`recipe`)、`MeasurementSession`、CLI、実行記録 | `examples/` のプロジェクトを `measure` で最後まで実行できる |
| **P4 キャリブとスポット** | 合成キャリブボード、`BoardHomography`、`SpotPlanner`、SpotDef XML 出力 | 既知の H を復元でき、旧スポット XML と一致する |
| **P5 解析** | 結果 CSV の読み込み、白色板正規化、BRDF の復元と出力(形式は要相談) | 往復テストで誤差が目標内 |
| **P6 実機ドライバ** | `Rc8Arm`(b-CAP)、`TopconImager`(`hs_api`)をビルドオプションで追加 | 実機で低速・小動作から検証する |
| **P7 ドキュメント** | 使い方、装置セットアップ手順、トラブルシュート、設計の説明 | 初めての人が資料だけで測定できる |

P0〜P5 は実機なしで進められます。P6 は研究室の PC で、実機と SDK が使える環境が必要です。

### 実機導入時の安全策(P6)
- 初回は低速・小振幅で動かし、動作前に可動域と干渉チェックを必ず通す。
- 非常停止(`emergencyStop`)を、すべての動作で即時に呼べるようにする。
- モーター ON/OFF と接続は、セッション単位で行う(旧は 1 動作ごと)。

## 7. 主な判断事項

| 事項 | 推奨 | 理由 |
|---|---|---|
| ビルドシステム | **CMake に移行**(Visual Studio からもそのまま開ける) | テストと CI を組みやすい。vcpkg のマニフェストとも相性がよい |
| テストフレームワーク | Catch2 | 軽量で、vcpkg から入る |
| 設定形式 | TOML(`tomlplusplus` が既に入っている) | 人が読み書きしやすい。コメントを書ける |
| 行列ライブラリ | Eigen に統一(`glm` と `opencv` の行列は使わない) | 重複を避ける。OpenCV は画像処理(ホモグラフィ・検出)に限定 |
| 角度の単位 | 内部は**ラジアン**、境界(CSV、RC8、画面)でだけ度に変換 | 旧は度とラジアンが混在してバグの温床になっていた |
| 出力形式 | まず CSV(旧と互換)。将来 HDF5 などは別途 | 旧データと比較しやすい |

## 8. リスクと対策

| リスク | 対策 |
|---|---|
| 旧システムの座標系の約束(§3.3)を取り違える | 旧データとの照合テストを P1 で最初に作る |
| 旧データの装置パラメータが不明 | 照合時に差分を記録し、パラメータの履歴を `setup.toml` として残す |
| TOPCON SDK が使える PC が限られる | `ISpectralImager` の実機実装は別ライブラリにし、ビルドオプションで切り替える |
| 実機での干渉・衝突 | モックの段階で干渉チェックを実装し、実機では低速から検証する |
| 仕様が「旧のバグ込み」で固まってしまう | 旧と違う結果は、どちらが正しいかを記録して、バグなら新側を正とする |
